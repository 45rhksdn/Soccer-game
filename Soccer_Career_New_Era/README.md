# Soccer Career — New Era

독립적인 한국어 싱글플레이 축구선수 커리어 웹게임. **0.3.0 / 라이벌과 주간 일정**.
원작의 소스·그래픽을 사용하지 않았으며, 원작의 확인되지 않은 기능을 사실로 주장하지 않는다. 학교·상대·선수는 가상이다.

## 플레이 — 0.3 라이벌과 주간 일정

1. 선수를 생성하면 천재/실전파/행운아 중 하나를 무작위로 받고, 동갑·동포지션·다른 학교의 라이벌이 생긴다.
2. 홈의 **이번주 일정 진행**에서 월~일 7일의 훈련/휴식을 설정한다. 최근 확정 일정은 다음 주에 유지된다.
3. 토요일은 경기일이다. 일정 진행이 경기 화면에서 멈추며 관전·행동 선택·빠른 진행을 사용할 수 있다.
4. **결과 반영 · 남은 일정 진행**을 누르면 일요일까지 처리하고 성장노트와 주요 뉴스를 갱신한다.
5. 라이벌 메뉴에서 능력·주간 경기·관심 구단을 비교한다. 라이벌은 은퇴까지 같은 ID로 성장·이적한다.
6. 시즌 종료에 계약 제안을 비교한다. 제안은 14일 후 사라지며, 모든 제안이 만료되면 **새 계약 구직**으로 새 제안을 요청할 수 있다.
7. 비시즌에도 7일 훈련 일정을 진행할 수 있다. 다음 시즌은 시즌 메뉴에서 시작한다.

휴양은 게임 내 5만원, 초기 생활비는 100만원, 고교 재학 중 주 2만원을 받는다. 실제 결제는 없다. 능력치는 최대 100이다. 기존 저장은 v4로 자동 업그레이드하며 선수·기록·진행 중 경기를 보존한다. 신규 특성의 경기 효과는 다음 새 경기부터 적용된다.

## 개발 실행

Node.js 22 이상 권장. 별도 API 키·DB 서버·유료 API가 필요 없다.

```sh
npm ci
npm run dev
```

Vite가 표시하는 주소를 연다. LAN 환경을 지원하지 않는 제한된 런타임에서는:

```sh
npx vite --host 127.0.0.1 --port 4173
```

## 빌드 및 배포

```sh
npm run build
npx vite preview --host 127.0.0.1 --port 4173
```

`dist/` 전체를 HTTPS 정적 호스팅에 배포한다. SPA 루트는 index.html. 상대경로 빌드로 하위 경로 배포도 가능하다. 사이트별 원본(origin)이 바뀌면 기존 IndexedDB가 분리되므로 JSON으로 옮긴다.

PWA는 프로덕션 빌드에서만 활성화된다. 최초 온라인 로드와 캐시 완료 후 오프라인 실행 가능하도록 서비스워커가 앱 자산을 미리 저장한다. iPhone Safari에서 HTTPS 주소 열기 → 공유 → 홈 화면에 추가. iOS 실기기 홈 화면 설치·OS의 저장소 제거 동작은 별도 확인이 필요하다. 사설 호스팅의 인증 게이트는 호스팅 환경에 따라 오프라인 첫 진입을 제한할 수 있다. 앱에는 자체 로그인·원격 저장 기능이 없다.

## 테스트

```sh
npm test
npx playwright install chromium
npm run test:e2e
```

Playwright는 테스트 전용 Vite 서버를 127.0.0.1:4180에 실행한다. 기본 프로젝트는 Desktop Chrome 및 iPhone 화면 크기를 사용하는 Chromium이다. **iPhone 장치 에뮬레이션은 Safari/WebKit 검증과 다르다.** 설치된 Chromium을 쓰려면 `CHROMIUM_PATH` 환경변수로 실행 파일을 지정할 수 있다. CI 결과는 `reports/`에 기록된다.

배포 빌드/오프라인 테스트는 `npm run build` 후 `PWA_TEST=1 npm run test:e2e`로 실행한다. 상세 실측값은 TEST_REPORT.md와 reports/*.json 참조.

## 구조

- `src/engine.ts`: DOM 없는 결정론적 축구 엔진, 고정 시간 간격, 행동 유틸리티
- `src/career.ts`: 생성·훈련·성장·선발·경기 결과·시즌 전환
- `src/world.ts`: 24구단/480선수, 리그, 감독, 이적, 계약, 신인/노화
- `src/development.ts`: 특성·7일 일정·라이벌·뉴스·관심 구단
- `src/WeeklyPanels.tsx`: 주간 일정·성장노트·라이벌 화면
- `src/roles.ts`: 포지션별 핵심 능력 평가
- `src/WorldPanels.tsx`: 선수단·리그·이적·커리어 화면
- `src/storage.ts`: 버전 검증·마이그레이션·체크섬·IndexedDB·백업
- `src/Pitch.tsx`: Canvas 경기 표시 (시뮬레이션을 변경하지 않음)
- `src/App.tsx`: 반응형 React 화면과 입력
- `scripts/sw.mjs`: 빌드 자산 해시 기반 서비스워커 생성
- `tests/`: Vitest 엔진/밸런스 + Playwright 사용자 흐름
- ARCHITECTURE.md / GAME_DESIGN.md / ROADMAP.md: 전체 프로젝트 확장 설계

## 데이터와 복구

저장은 기기/브라우저별로 독립적이다. 브라우저 데이터 삭제 전에 반드시 JSON을 내보낸다. 저장 실패는 화면 알림으로 표시한다. 읽기 오류가 나면 저장 관리에서 해당 슬롯의 직전 백업을 불러온다. 가져오기는 체크섬/버전을 검증한 뒤 현재 슬롯에 기록하며 기존 정상 데이터는 직전 백업으로 보존된다. 체크섬은 우발적 손상을 찾기 위한 용도이며 암호학적 서명이나 치팅 방지 기능이 아니다.

## 개발 범위

PC/모바일 반응형 UI, 생성·훈련·경기·성장·저장·다음 경기까지 구현했다. 패스/슈팅은 위치 기반 확률 계산이고 공의 비행을 표시한다. 완전한 물리 축구나 전문 경기 AI 수준은 아니다. 구체적인 미구현 항목은 ROADMAP.md에 명시했다.
