# Soccer Career — New Era

독립적인 한국어 싱글플레이 축구선수 커리어 웹게임. **0.4.0 / 다중 특성 · 실제 고교 발굴 · 선수 변경하기**.
원작의 소스·그래픽을 사용하지 않았으며, 원작의 확인되지 않은 기능을 사실로 주장하지 않는다. 학교명·지역만 실제이며(공개 대회 자료로 축구부 운영 확인), 선수·감독·구단·상대는 모두 가상이다.

다음 담당자(ChatGPT Work / Claude)는 먼저 [HANDOFF.md](HANDOFF.md)를 읽는다.

## 플레이

1. **새로운 커리어 시작** → 두 가지 방법 중 선택한다.
   - **실제 고교에서 발굴**(기본): 시·도 지도 또는 검색으로 실제 축구부가 있는 고등학교를 고르면 가상의 후보 6명이 나온다. 나이·포지션·체격·능력치 13종·잠재력 추정·특성을 비교하고 한 명을 골라 시작한다. **새 후보 목록 생성**으로 다른 후보를 볼 수 있으며, 학교별 목록은 새로고침·재접속 후에도 같다.
   - **직접 만들기**: 기존처럼 이름·포지션·체격을 입력하고 가상 고교 3곳 중 하나에 입단한다.
2. 선수는 34종 중 특성을 **0~3개** 가진다(없을 수도 있음). 긍정 특성은 초록색 `+`, 부정 특성은 빨간색 `−` 아이콘으로 표시된다. 라이벌과 NPC 480명도 같은 규칙의 특성을 가진다.
3. 홈의 **이번주 일정 진행**에서 월~일 7일의 훈련/휴식을 설정한다. 토요일은 경기일이다. 피로가 60% 이상인 날의 훈련은 부상 위험(기본 2%)이 있다.
4. **선수 변경하기**에서 최대 3명의 선수 커리어를 슬롯별로 따로 보관하고 전환한다. 전환 전 현재 선수를 먼저 저장한다. 이미 선수가 있는 슬롯에 새 선수를 시작하면 확인 후 교체되며, 기존 선수는 **교체 전 선수**로 보관되어 복원할 수 있다.
5. 라이벌·시즌·이적·14일 제안 만료·재구직·비시즌 훈련은 0.3과 같다.

휴양은 게임 내 5만원, 초기 생활비 100만원, 고교 재학 중 주 2만원. 실제 결제는 없다. 능력치 최대 100.

## 개발 실행

Node.js 22 이상 권장. 별도 API 키·DB 서버·유료 API가 필요 없다. 저장소에서는 이 폴더(`Soccer_Career_New_Era/`)가 프로젝트 루트다.

```sh
npm ci
npm run dev
```

## 빌드 및 배포

```sh
npm run build
npx vite preview --host 127.0.0.1 --port 4173
```

`dist/` 전체를 HTTPS 정적 호스팅에 배포한다. 상대경로 빌드로 하위 경로 배포도 가능하다. 사이트 주소(origin)가 바뀌면 IndexedDB가 분리되므로 JSON으로 옮긴다. PWA는 프로덕션 빌드에서만 활성화된다.

**배포 주의:** 운영 사이트(Work 배포)에는 이 저장소에 없는 최신 변경이 있을 수 있다. 이 브랜치를 운영 사이트에 덮어쓰기 전에 반드시 최신 Work 소스와 비교·병합한다(HANDOFF.md 참고).

## 테스트

```sh
npm test                                   # Vitest: 단위·회귀·밸런스·장기 커리어 (71개)
npx playwright install chromium
npm run test:e2e                           # PC + iPhone 화면 크기 Chromium
npm run build && PWA_TEST=1 npm run test:e2e   # 프로덕션 빌드 + 오프라인
WEBKIT=1 npx playwright test --project=iphone-webkit   # 선택: Safari 엔진(WebKit)
```

**iPhone 화면 크기 Chromium·WebKit 에뮬레이션은 실제 iPhone Safari 검증이 아니다.** 실제 기기 Safari·홈 화면 설치는 아직 테스트하지 않았다. GitHub Actions(`.github/workflows/ci.yml`)가 push/PR마다 빌드·단위·브라우저 테스트를 실행한다.

## 구조

- `src/engine.ts`: DOM 없는 결정론적 축구 엔진
- `src/career.ts`: 생성·훈련·성장·선발·경기 결과·시즌 전환 (`CareerPreset`, `schoolRef`)
- `src/world.ts`: 24구단/480선수(특성 포함), 리그, 감독, 이적, 계약, 신인/노화
- `src/development.ts`: 7일 일정·훈련 부상·라이벌·뉴스·관심 구단
- `src/traits.ts`: **특성 데이터 표와 효과 계층**(사용자·라이벌·NPC 공통)
- `src/schools.ts`: **실제 고교 축구부 목록(73개교, 17개 시·도)과 출처**
- `src/scouting.ts`: **재현 가능한 가상 후보 생성**과 후보 → 커리어 시작
- `src/storage.ts`: 버전 검증·v1→v5 마이그레이션·체크섬·IndexedDB·백업·교체 전 선수 보관·스카우트 상태
- `src/App.tsx`, `WeeklyPanels.tsx`, `WorldPanels.tsx`, `ScoutPanel.tsx`, `PlayerSlots.tsx`, `TraitBadges.tsx`: 화면
- `tests/`: Vitest + Playwright, `tests/fixtures/`: 0.3 코드로 만든 실제 v4 저장 파일

## 데이터와 복구

저장은 기기/브라우저별로 독립적이다. 슬롯 3개(`slot1..3`)와 각 슬롯의 직전 백업(`backup1..3`), 교체 전 선수(`archive1..3`), 스카우트 상태(`scouting`)를 IndexedDB에 저장한다. 직전 백업은 내용이 달라질 때만 갱신되고, 읽을 수 없는 슬롯은 백업으로 옮기지 않는다. 브라우저 데이터 삭제 전에는 JSON으로 내보낸다. 저장 형식은 **v5**이며 v1~v4 저장은 자동 변환된다(기존 특성 보존). 체크섬은 우발적 손상 검출용이며 보안 서명이 아니다.
