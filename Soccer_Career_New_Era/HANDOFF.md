## 2. 가장 중요한 주의 — 운영 사이트의 최신 Work 코드

- 0.3 ZIP은 운영 사이트(`soccer-career-new-era.spicy-vine-2764.chatgpt.site`)보다 오래된 스냅샷이다. 운영 화면에는 `선수 변경하기` 메뉴가 있었지만 ZIP에는 없었다.
- 이 브랜치의 `선수 변경하기`는 **ZIP을 기준으로 새로 구현**한 것이다. Work의 구현 코드를 본 적이 없으므로 동작·저장 키가 다를 수 있다.
- **이 브랜치를 운영 사이트에 그대로 배포하지 말 것.** 최신 Work 소스를 확보하면 `main`에 별도 커밋으로 올린 뒤 이 브랜치와 diff·병합한다. 두 구현의 저장 키(아래 4절)가 겹치거나 다르면 마이그레이션을 추가한다.

## 3. Work ↔ Claude 교대 규칙

1. 시작 전: `git pull`, 이 문서·CHANGELOG 읽기, `npm ci && npm test && npm run build`.
2. 작업은 새 브랜치에서, 기능별 커밋. 원본 전체 재작성·저장 데이터 초기화 금지.
3. 저장 형식을 바꾸면 `SAVE_VERSION`을 올리고 `storage.ts`의 `validate()`에 이전 버전 → 새 버전 변환을 **추가**한다(기존 단계 삭제 금지). `tests/fixtures/`에 이전 버전 실제 저장 파일을 남기고 변환 테스트를 쓴다.
4. 특성·학교를 추가할 때 기존 id는 절대 바꾸거나 재사용하지 않는다(저장에 id가 들어 있다).
5. 끝나면 이 문서의 체크리스트·테스트 결과·알려진 문제를 갱신한다.

## 4. 저장 형식 v5 (IndexedDB `soccer-career-new-era` / store `saves`)

| 키 | 내용 |
|---|---|
| `slot1..3` | 선수 커리어 (SCNE JSON 문자열, 체크섬 포함) |
| `backup1..3` | 해당 슬롯의 마지막으로 **달랐던** 저장. 읽을 수 없는 슬롯은 백업으로 옮기지 않음 |
| `archive1..3` | 새 선수로 교체되기 전의 선수(교체 전 선수). 자동 저장이 건드리지 않음 |
| `activeSlot` | 마지막으로 플레이한 슬롯 번호 |
| `scouting` | `{seed, lists:{[schoolId]:목록번호}}` 스카우트 상태(커리어와 분리) |

v4 → v5 변경:
- `development.trait`(문자열) → `development.traits`(문자열 배열, 최대 3). 기존 특성은 `[기존 특성]`으로 **그대로 보존**.
- `development.rival.trait` → `development.rival.traits` (같은 방식).
- `world.clubs[].roster[].traits` 추가. 기존 NPC에는 `hash(world.seed, 선수 id)`로 결정론적으로 부여(월드 RNG 소비 없음).
- `Career.schoolRef?: {id,name,region}` 추가(선택). `school`(0~2)은 기존처럼 가상 리그 구조의 슬롯이며 그대로 유지.
- 알 수 없는 특성 id는 버리지 않고 보존(효과는 무시, 회색 표시) → 향후 Work가 특성을 추가해도 저장이 깨지지 않음.

**호환성 한계:** 0.3 코드(운영 Work 포함)는 `version===4`만 읽으므로 v5 저장을 열 수 없다. 반대 방향(v1~v4 → v5)은 자동 변환된다. Work가 이 브랜치를 병합하면 이 문제는 사라진다.

## 7. 알려진 문제와 설계상 결정

- 특성 34종(긍정 21, 부정 13). 브리프의 초기 확률(일반 6%·희귀 3%)을 그대로 쓰면 특성 없는 선수가 약 13%뿐이라 일반 3%·희귀 1.5%로 낮췄다(`RARITY_CHANCE`). 조정 시 분포 테스트는 표 기반이라 그대로 동작한다.
- NPC에게 효과가 없는 특성: 부상 관련(유리몸·회복력·강철 체력·강철몸·잔부상·저질 체력), 감독 신뢰(성실함·감독과 불화), 슈퍼 조커, 라이벌 의식·독학파. 해외 체질·향수병은 NPC 연간 성장에 반영.
- 특성 `플레이메이커`는 플레이 스타일 `플레이메이커`와, 특성 `대기만성`은 성장 유형 `대기만성형`과 이름이 비슷하다(서로 다른 시스템).

- 훈련 부상(피로 60% 이상, 기본 2%)은 0.4에서 새로 생긴 규칙이다. 기존 주간 일정에는 훈련 부상이 없었다(레거시 `train()`에만 있었음).
- 가상 고교 3곳의 `boost`(패스/스피드/수비)는 화면에만 표시되고 효과가 없다(0.3부터).
- 실제 고교를 고르면 플레이어 소속 가상 구단 이름이 그 학교명으로 바뀐다. 리그 상대·라이벌 학교는 가상.
- 운영 Work의 `선수 변경하기`·기타 최신 변경과의 병합은 아직 하지 않았다(2절).
